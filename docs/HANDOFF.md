## What the system is

A private IB Diploma study site (exams May 2028), now **multi-user**: an admin account creates student
accounts, each with their own subject list and their own data. It has two parts:

- **Study site** (repo root, generated by `tools/build_site.py`). It contains:
  - subject hubs with syllabus checklists (tick plus red/amber/green per topic);
  - deadlines, plan, core (TOK/EE/CAS), IA pages;
  - a library of the private PDFs.

  It runs locally only.
- **Practice app** (`app/`). It contains:
  - topic notes;
  - quiz (MCQ marked automatically, written answers self-marked);
  - Leitner flashcards;
  - a "Today" panel on the home page (due cards, weakest-topic quiz, this week in class);
  - exam-style practice (Chemistry Paper 1A/1B-style banks, Biology data response), confidence ratings and a past-paper score log;
  - a coursework planner (Biology/Chemistry scientific investigation, Maths exploration);
  - a read-only weekly summary page for a parent (`summary.html`);
  - an upload page.

  `tools/build_deploy.py` builds it into `deploy/nevaib/` for https://rametric.com/nevaib/. A small PHP API (`server/api.php`, PHP 7.2) handles login and cross-device sync.

Stack: static HTML, vanilla JS, JSON content, browser localStorage, one PHP file, and Python for build and validation scripts. There are no frameworks and no runtime dependencies.

## Data model and sync (short version; details in DEVELOPMENT.md)

- **Progress lives in localStorage:**
  - `fc-state` (per card: box, due, seen, t);
  - `q-errors` (missed questions, keyed `bank#id`);
  - `quizlog`;
  - `chk:*` checklist rows;
  - `week:*`;
  - lists (`tok-objects`, `ee-ideas`, `io-issues`, `ia-debriefs`);
  - coursework planner (`cw-progress`: per-item ticks, stage notes and her own dates, merged per record);
  - `res-*`;
  - user cards and banks (`fc-user`, `fc-userdecks`, `q-userbanks`, `fc-deleted`, `fc-edits`).
  - `pp-scores` (past-paper score log on the Quiz page; records keyed by `id`, deletions kept as `{id, deleted, ts}` tombstones, merged per record by newest `ts`).
  - Confidence ratings: quiz results carry `conf` (`sure`/`guess`); `quizlog` entries may have a `conf` tally and `q-errors` records `lastConf`/`sureWrong`. Older records without these fields stay valid.
- **When logged in, the server holds one JSON state file per user.** Every save:
  - takes a per-user lock;
  - copies the previous version to `state/history/<user>/` (newest 30 kept);
  - writes atomically and bumps `rev`.

  A save based on an outdated `rev` gets a 409. The client then merges and retries. On any one browser, each
  account's data lives in its own localStorage scope (`<user>:<key>`), so a second student logging in on the
  same device starts empty (filled from the server) and can never see or overwrite the first student's local
  data; dirty markers and safety snapshots are scoped the same way.
- **Merge rules:**
  - SRS state, missed questions and the quiz log merge record by record (newest wins);
  - anything this device changed since its last sync keeps the local value;
  - anything else takes the server value;
  - a device's first sync unions both sides.

  Before any local value is replaced, it is snapshotted locally.
- **Backups:**
  - "Download full backup" on the Cards page saves every progress key;
  - `api.php?action=export` saves the server copy;
  - restore validates the file, shows a summary, merges by default, and can be undone.

**Ask an AI (Nov 2026, hardened 19 Nov):** each topic note has a short mode menu (explain, quiz me, unfamiliar data-response, help with wrong answers) and an assistant picker (Gemini by default; also ChatGPT, Claude, Perplexity). A click copies the filled prompt synchronously while the page still has focus (execCommand first, async Clipboard API as backup) and then opens the preferred assistant in a new tab with `opener` cleared — she pastes with Ctrl+V. If the copy fails, the tab is not opened and the failure stays visible in the card; a **Copy the prompt again** button appears after the first prompt (and resets when she opens another note, so no stale prompt is copied), and a blocked pop-up gets its own hint. Double-clicks within 600 ms are ignored, and `subjectNames` in the JSON gives proper course names for subjects whose ids have no `-hl/-sl` suffix (French, History). There is no preview and no prompt-in-the-URL. All wording lives in `library/ai-prompts.json` (`default_ai`, `assistants`, shared `preamble`, `modes[].template`). Placeholders (`{subject}`, `{level}`, `{topic}`, `{understandings}`, `{keyterms}`, `{wrong_questions}`) are documented in that file's `_doc` field and are filled from the open note (key-idea cues, key terms, and — for the review mode — stems from `q-errors` on that note's linked quiz items). The prompt never includes her name, school or grades. Preferred assistant is `localStorage` key `ai-pref`: device-only (LOCAL_ONLY, per-user scoped since the multi-user upgrade), not in `SYNCED_KEYS`, so it is not backed up or quarantined. To change the text, add a mode, or switch the default assistant, edit `library/ai-prompts.json` and run `./dev.sh test`. Tests: `tests/js/ai-prompt.test.js` (including the copy tri-state) and an e2e click on the Biology A1.1 note.

**Multi-user (live since 19 Nov, PR #17):** the site now supports several students with separate data and subject lists.

Tests: `tests/js/store.test.js` + `tests/js/scope.test.js` + e2e section 4.
- **Subject profiles**: each account has a synced `profile.subjects` list (set by the admin at creation, editable via `set-profile`); `assets/profile.js` filters nav links, dashboard cards, hub sections, quiz banks, decks, notes, library subjects, coursework tracks, the Today panel and tagged deadlines to those subjects (legacy id spellings are normalized). Accounts without a profile (neva) see everything, exactly as before. Tests: `tests/js/profile.test.js`, e2e section 5.

## How notes are authored and validated

1. Notes are written outside the repo as one JSON file per topic, using schema v1 (see DEVELOPMENT.md, "Topic notes"). The wording is original. Only the official topic codes and statement numbers are reused.
2. `python3 -I tools/import_topic_notes.py <draft-dir>` copies the notes into `library/topic-notes/<subject>/`, copies the syllabus maps into `library/syllabus/`, and rebuilds the manifest. It never reads `sources/` or `_build/`, and it refuses any file that mentions a local path.
3. `./dev.sh validate` fails on any of these:
   - missing fields;
   - malformed items;
   - a bad Paper 1A answer index;
   - a linked bank, deck, question id or card id that doesn't exist;
   - a manifest that doesn't match the files.
4. `python3 -I tools/build_site.py` adds the "study notes" links to the checklist rows.
5. `./dev.sh test`, plus `./dev.sh e2e`, which opens every note and checks that the quiz and cards links start on the linked items.

The notes are drafts (`status: "draft"`). Each one says it is not IB material, not an IB markscheme, and not a prediction of exam questions.

## Get it onto your laptop

Your copy is at `~/Projects/ibsystem`.

```bash
cd ~/Projects/ibsystem
git status                      # must be clean; otherwise: git stash
git switch main && git pull
./dev.sh test                   # pytest + node + php -l (needs uv, node >= 18, php)
./dev.sh start                  # http://127.0.0.1:8018/app/index.html
```

Other commands:
- `./dev.sh validate`: content validator.
- `./dev.sh e2e`: browser tests (needs Chrome; installs puppeteer-core into `tests/e2e` once).
- `./dev.sh build`: rebuilds the site and the deploy folder.
- `./dev.sh deploy`: dry run only. A real upload needs `--confirm` (see NEXT-STEPS, step 1).
